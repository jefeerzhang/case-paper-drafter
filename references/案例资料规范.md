# 新案例资料规范

本规范适用于自己提供的新案例材料。首次输入材料、追加材料或换Agent时，读取本规范，再按[新案例执行入口](新案例执行入口.md)执行。它说明材料如何存放、整理、定位和考察；研究路线仍以五份V3核心为准。

不要求每个案例同时拥有问卷、访谈和录音。已有材料按其实际形成方式登记，缺少材料写成具体缺口。先判断材料能支持什么问题与主张，再决定补采内容。本规范没有规定统一问卷样本量、访谈人数、信效度阈值或期刊强制格式。

## 1. 推荐存放结构

一个研究案例使用一个总目录。材料、成果和受限归档分开。目录是推荐组织方式，已有目录可以保留，但要提供用途对照与真实路径。

```text
案例名称/
├─ 材料/                         ← Agent读取与index_materials.py登记的范围
│  ├─ 00_资料说明/
│  │  ├─ 材料输入说明.md
│  │  └─ 已知缺口与矛盾.md
│  ├─ 01_原始资料/
│  │  ├─ 01_问卷/                ← 问卷版本、原始导出、施测记录
│  │  ├─ 02_访谈/                ← 提纲、现场记录、实际访谈记录
│  │  ├─ 03_录音与视频/
│  │  ├─ 04_观察与过程记录/
│  │  ├─ 05_内部档案与业务数据/
│  │  └─ 06_公开资料/
│  ├─ 02_整理资料/
│  │  ├─ 转录文本/
│  │  ├─ 匿名化副本/
│  │  ├─ 问卷清洗与编码/
│  │  └─ 摘录与翻译/
│  └─ 03_理论与方法文献/
├─ 成果/                         ← init_case.py的--case-dir
│  ├─ 案例配置.json
│  ├─ 材料登记.json
│  ├─ 事实与证据.csv
│  ├─ 执行记录.md
│  └─ 00—09阶段成果与论文草稿
└─ 受限归档/                     ← 身份映射、受限原件与使用范围记录
```

材料目录只放本次拟交付Agent的文件。能够共享的原件放入 `01_原始资料/`；不拟共享的原件保存在 `受限归档/`，材料目录放实际核对过、允许交付的副本。身份映射表与材料共享目录分开。向Agent提供材料目录与成果目录，受限归档不作为登记脚本的扫描根目录。

原件保持原内容。转录、清洗、匿名化、翻译和摘录另存文件，并登记其原件关系。分析编码、解释矩阵和论文稿放成果目录。缺少原件时保留整理文件，注明原件未提供和实际核查范围，不重建不存在的原件。

## 2. 文件命名、编号与共同登记字段

建议命名为 `资料组编号_形成日期_主体或角色_材料类型_人工版本.扩展名`。示例是命名演示，不代表真实案例：

```text
SUR-001_202405_企业A员工_问卷工具_v01.pdf
SUR-001_202406_企业A员工_原始回答_v01.csv
INT-001_20240618_P01部门负责人_录音_v01.m4a
INT-001_20240618_P01部门负责人_转录_v01.txt
INT-001_20240618_P01部门负责人_摘要_v01.md
OBS-001_20240620_项目A_现场观察_v01.md
DOC-001_日期未知_企业A_流程文件_v01.pdf
```

文件名使用实际日期，未知时写“日期未知”。身份标签按本次共享范围填写，匿名时仍保留分析所需的角色、层级、参与关系和时期。文件名不要填补资料中未确认的职位、时期或内部身份。

脚本分配的 `S0001` 是物理文件编号；`INT-001` 是一场访谈的资料组编号；`P01` 是参与者标签；`E0001` 是具体证据编号。它们分别登记文件、形成过程、人物和证据，不能互换。一场访谈的录音、转录、译文和摘要属于同一来源过程，不自动算四份独立证据。问卷的受访者行编号也不是文件编号或独立案例编号。

文件名中的 `v01` 是人工版本；登记JSON的 `version` 追踪同一路径的字节变化。它们不是同一个编号。旧版本仍用于分析时，保留旧文件，而不只保留哈希。技术操作见[脚本使用说明](脚本使用说明.md)。

| 字段 | 登记要求 | 在脚本登记中的位置 |
| --- | --- | --- |
| 来源形成者 | 谁作出陈述、创建文件或导出数据；与采访者分开 | `metadata.source_actor` |
| 取得或研究执行者 | 谁采访、观察、导出、下载或整理；说明实际动作 | 扩展字段 `metadata.collection_actor` |
| 材料类型 | 原始回答、录音、现场笔记、转录、回顾纪要、公开报道、理论文献分别命名 | `metadata.material_type` |
| 形成时间与事件时期 | 文件形成日期、访谈日期与回忆事件时期分列；未知保留未知 | `metadata.material_formed_at`、`metadata.event_period` |
| 资料组与对象 | 访谈/问卷批次及焦点案例、项目、部门、参与者关系 | 扩展字段 `metadata.record_group_id`、`metadata.case_unit_id`、`metadata.participant_ids` |
| 原件与派生关系 | 已登记原件用S编号关联；未共享原件用本地归档编号，并注明未回读 | 扩展字段 `metadata.parent_source_ids`、`metadata.unshared_origin_id`、`metadata.derivative_type` |
| 原语与译本 | 原语、翻译执行者、译本版本及实际核对范围 | `metadata.original_language`、`metadata.translation_version`；其他信息用扩展字段 |
| 原材料定位 | PDF文件页/印刷页、文本行、表名/单元格、录音时间戳；摘录保留上下文位置 | 在 `事实与证据.csv` 的 `locator`，正文引用同一证据编号 |
| 整理与核对范围 | 人工/AI执行的动作、工具版本、已核对片段、未核对范围与纠错记录 | 扩展字段 `metadata.processing_method`、`metadata.verified_ranges` |
| 公开来源 | 作者/发布主体、原链接、发布日期、取得日期、本地快照 | 扩展字段 `metadata.source_url`、`metadata.accessed_at`；发布日期另登记 |
| 本次使用范围 | 实际允许的研究使用、引用、共享范围；未确认时注明 | 扩展字段 `metadata.sharing_scope`；受限记录另存归档 |

启用脚本时在 `材料登记.json` 的 `metadata` 内填写。脚本保留人工元数据，当前CSV派生表只展示既有字段，扩展字段在JSON中查阅。未启用脚本时，把同样信息保存在材料输入说明及事实表。操作系统修改时间不代表事件时间或材料形成时间。

## 3. 各类资料的规范与考察要点

### 3.1 问卷

**存放。** 问卷工具和各次施测版本、原始回答导出、样本/施测记录分别存放。编码表、清洗数据、清洗规则、分析程序和结果另存整理或成果目录。CSV/XLSX可以保存数据；提供只读的问卷题目版本。只有平台结果截图时，按截图实际范围登记，保留原始导出缺口。

**整理要求。** 至少能对应题目编号、完整题干、选项、量表方向、版本和回答字段。每条回答保留匿名行编号及实际可用的案例/部门/角色信息。记录招募对象、取得渠道、施测时期、实际回收数量、有效数量、重复/缺失/剔除规则。未回答、无法判定、跳题和真实零值分开。每项重编码、反向题、合成指标和删除都保留规则与前后对应；原始数据不覆盖。

**考察。** 问卷在本案中用于背景描述、补充感知，还是承担统计检验？填答人是否覆盖待解释的对象和时期？便利接触、组织安排填答、匿名作答和重复施测分别说明。多个员工的回答不自动成为多个独立企业案例。便利样本不自动代表全体员工，态度分数不自动证明行为变化或机制成立。

量表来自已有文献时保存真实出处、原题与改动；自编题说明设计依据和实际试测情况。承担统计检验时，按具体设计考察测量、样本、缺失、分析单位和实际检验条件，不以统一样本量或信度阈值代替方法判断。只保留统计汇总时，不能写成已经复核原始个体数据。

### 3.2 访谈、公开采访与访谈笔记

**存放。** 提纲、实际访谈记录、现场笔记、事后纪要分开；录音与转录按同一访谈组关联。参与者真实身份映射另存受限归档。没有录音的访谈可以使用实际笔记，明确记录类型和缺失条件。

**整理要求。** 每次实际访谈有组编号、日期、地点或线上方式、采访者、参与者角色与选取理由、覆盖事件时期、实际时长和记录方式。区分提纲计划与真正问过/回答过的问题。回顾纪要保留整理日期；转述与可核对的直接原话分开。公开采访或别人实施的访谈，登记原采访者及取得方式，不写成自己实施的访谈。

**考察。** 参与者是否亲历该事件，还是转述他人判断？他在决策、执行和评价中的位置是什么？能否说明具体事件、时间、行动主体、选择依据、结果和反例？管理层、执行者、合作方及受影响人员的视角是否覆盖本研究问题？实际选取逻辑是否支持当前设计？不能用一个管理者的评价代替员工共识。

问法与回答分开保留，关键反问、限定条件、否定和矛盾不删除。只剩摘要或事后概括时，按其可支持的陈述使用，不生成逐字引语。访谈人数依据问题和材料覆盖判断；没有实际编码、比较和补采记录时，不宣布理论饱和。

### 3.3 录音与视频

**存放。** 保存能够交付的原始音视频及其文件信息；MP3、M4A、WAV、MP4均可以登记，不强制转码。压缩、降噪、分段、剪辑和转写另存派生文件。片段有原文件编号与起止偏移，剪辑版不替代原记录。不可交付的原件保留在受限归档，说明实际交付副本的范围。

**整理要求。** 关联访谈/会议组编号、真实录制时间、录制者、参与者标签、时长、录制起止及中断情况。每段或换人时给转录起始时间戳；论文拟用片段记录起止时间戳与对应文本行。听不清、讲话者未知、删节分别标记。摘要、逐字转录和研究者解释分别保存。跨语材料关联原语、译者、译本与核对位置。

**考察。** 录音是否完整，是否存在漏段、剪接、重叠讲话或说话者识别不确定？关键数字、时间、否定词、决策描述是否回听？受访者是在报告亲历事实、表达评价、设想未来，还是转述他人？自动转写错误是否改变主张？语气、笑声和沉默只有在研究问题与实际上下文支持下才进入解释。

用于论文的直接引语、关键数字、关键决策和核心论证片段逐项回听；其他部分按任务抽检并登记范围。只核对部分，就写部分核对。AI转录与摘要须注明实际工具和人工核对范围，不能把自动生成文本当作已经听过原录音。

### 3.4 其他参考资料

| 类型与存放位置 | 整理要求 | 重点考察 |
| --- | --- | --- |
| 现场观察、工作日志：原始资料/观察与过程记录 | 观察日期、场景、观察者角色、实际见闻、现场记录与事后整理日期；描述与推断分列 | 观察者实际进入范围、参与影响、未见过程；一次见闻能否支持长期变化 |
| 内部会议、制度与流程档案：原始资料/内部档案与业务数据 | 文件形成主体、日期、版本、生效/执行状态、会议参与者与具体定位 | 目标、草案、批准、实际实施和成效是否混称；会议纪要是否代表全部参与者意见 |
| 业务台账与系统数据：原始资料/内部档案与业务数据 | 原始导出、字段字典、导出者、覆盖时期、单位、分母、主体、缺失与口径变化；清洗另存 | 数据生成规则、对象覆盖、重复记录、前后可比性；率值变化来自分子还是分母 |
| 年报、公告、网页、媒体与公开访谈：原始资料/公开资料 | 原链接、本地快照、发布者、发布时间、取得时间、页码；转述关联原出处 | 原始发布还是转载；宣传、目标、实际结果分别识别；多次转载不是独立来源 |
| 理论与方法文献：材料/理论与方法文献 | 真实可读文件、作者、年份、题名、出版信息、标识符与拟用页码；已读范围明确 | 定义、适用层次、命题与原文是否对应；写法范例不能成为本案事实，理论卡不能替代原文 |
| 图片、扫描件、图表与OCR：按原资料类别存放；提取文本另存整理资料 | 原图/原PDF、文件页与印刷页、截取位置、表头/图注/单位；OCR关联原件 | 丢失页边、合并表格、字符/数字误识别；关键内容回看图像，不只读OCR |
| 第三方报告、二手笔记、AI整理文本：按来源存放；派生摘要放整理资料 | 原来源与实际作者/工具、日期、输入范围、改写方式、原件是否提供 | 哪些是可追溯事实，哪些是转述或建议；不能仅凭摘要补出不存在的访谈、执行程序或结论 |

## 4. 从文件到可用证据

材料登记说明文件存在，不等于其内容可靠。Agent回读原材料后，把具体片段与 `E` 证据编号绑定，再进入事实表、解释矩阵和提纲。

1. 对文件登记S编号、版本和哈希；对真实形成过程登记组编号。
2. 对拟用片段记录准确定位、直接支持的陈述及不能确认的解释。
3. 分开材料形成时间、事件时期、计划、观察、陈述和条件预测。
4. 对转录/译文/清洗数据回到其原件关系，记录真实核对范围。
5. 对同一事件保留相互冲突的材料、不同主体解释和未覆盖范围。
6. 把证据编号写进分析矩阵与提纲，保留需要补证的主张。

同一来源的不同文件不自动提供独立互证。原件未交付、来源无法核对或只有摘要时，仍可以提供研究线索，但引用和结论限定在实际可核查范围。把“无记录”“未回读”“没有发生”分别表述。

## 5. Agent的资料考察与接收条件

首次输入先盘点文件和真实读取能力，再按问题选择回读范围。每类材料记录：已读正文、已听片段、仅查看元数据或无法打开。不能把文件登记、转录生成或目录数量写成全文阅读完成。

把下表复制到 `00-任务范围.md` 的“资料输入与考察”部分。每项填写已核对、未核对或不适用，附S编号/组编号和具体位置。符合条件的继续分析，不因某类资料缺少而统一停止。

| 考察项 | 具体问题 | 记录与动作 |
| --- | --- | --- |
| 可读取范围 | 文件能否打开？实际读到正文、表格或录音哪些范围？ | 保留无法读取和未回读范围，安排必要转换 |
| 来源与执行者 | 谁形成、谁取得、谁采访/观察/导出？ | 未确认身份保持待确认，不补成自采材料 |
| 对象与单位 | 材料对应哪个案例、部门、项目、参与者或事件？ | 说明案例边界与嵌入关系，不以文件数代替案例数 |
| 时间与状态 | 资料何时形成，覆盖哪段事件？是计划、观察还是回顾？ | 保留空缺时期、回忆跨度和未实施事项 |
| 问卷与访谈过程 | 题目/提纲、版本、取样、实际执行和回答记录是否对应？ | 区分已执行与计划；写明设计尚缺条件 |
| 原件与整理链 | 转录、清洗、匿名化、翻译和摘要对应哪个原件？ | 保留父来源与核对范围；不可追溯片段标记限制 |
| 定位与版本 | 主张能否回到具体页、行、单元格或时间戳？ | 核对引用版本；变更材料后复核旧证据 |
| 数字与口径 | 单位、分子、分母、对象、时期与清洗规则是否明确？ | 不把缺失当零，不把子集结果推为全体 |
| 独立性与矛盾 | 是新来源、转载、同次访谈派生，还是重复样本？ | 关联重复关系，保留反例与分歧 |
| 问题与证据匹配 | 当前资料能支持描述、比较、机制解释还是条件方案？ | 按主张逐项判断证据缺口，不靠资料类型数量宣布充分 |
| 真实理论来源 | 概念和贡献所用文献实际可读、实际核查到哪里？ | 未核查定义与缺口保留待核查 |
| 使用与交付范围 | 拟交付材料、引用范围和匿名标签是否明确？ | 按实际范围交付；受限原件与身份映射另存 |

对每项拟用主张保存以下判断，而不是给整批资料一个笼统“合格”：

- **当前可用**：本主张的来源、定位、版本和实际证据范围能核对，结论不越界。
- **研究线索**：材料能提出问题，但不足以确认事实、直接引语、机制或效果。
- **需补件/回读**：明确缺哪个原件、数据字段、角色视角、时期或核对步骤。
- **不纳入本主张**：无关、重复、身份错误或无法支持当前主张；保留排除理由和原记录。

补件按对核心问题的影响排序。优先处理主张定位缺失、关键原话/数字未核对、材料身份混淆、重要时期/主体空缺和相互冲突的关键证据。新增资料可能改变分析范围或设计，记录改变依据。

## 7. 启用脚本与手工执行的边界

脚本按[脚本使用说明](脚本使用说明.md)登记文件并核查结构、版本和编号。本规范的取样适合性、访谈质量、原话准确性、数据口径、来源独立性及理论支持，由Agent结合真实材料考察并保存记录。三个脚本当前不自动转写录音、不执行OCR，也不自动判定上述研究条件。

只用文档时，把本规范与五核心一起交付；手工保持来源编号、定位和版本记录。使用完整执行包时，先读本规范与脚本说明，填写材料输入说明，确认材料范围，再初始化与登记。新资料追加后更新输入说明、材料登记和受影响的证据/分析成果。
