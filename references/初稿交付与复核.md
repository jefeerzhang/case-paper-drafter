# 初稿交付与复核

当资料分析与提纲已经形成，或用户提供现成分析要求续写时，读取本文件。它把V3第8—9步落实为初稿交付，不另增研究路线。详细动作和边界以《AI执行流程》、手册及当前证据为准。

## 1. 初稿的正文范围

交付可连续阅读的正文。根据所选路线组织题目、摘要、关键词、问题与理论对话、资料与方法、案例分析、讨论、结论及真实参考来源。可以合并或拆分章节，不把这些功能固定为统一章数或段数；不要强制所有案例三阶段。

正文的引言说明具体问题与当前文献核查范围；方法说清资料实际形成与分析程序；案例分析呈现实际证据、解释、比较和反例；讨论回应理论任务与边界；结论只概括本案所能支持的发现。问卷只用作背景时，不增加未执行的信效度或因果检验。公开资料与他人访谈按真实取得方式说明，不称为自己实施的访谈。

题目、摘要与结论的确定性不超过分析正文。没有理论原文时，把对应定义和对话留为待核查；不要凭模板添加真实作者、年份、DOI或虚构参考条目。参考文献只列实际可核查来源，未核查条目放待补清单。

## 2. 事实与写作的连接

每个核心经验主张在工作稿中绑定E编号与原定位；可以用段末注、表注或单独主张表，不要求每句都重复标记。事实表与证据矩阵保留S编号、文件版本、形成主体、事件期、材料身份与不能确认的解释。论文的表、图与正文使用同一口径和同一版矩阵。

说明限定主张而非扩大主张：一个管理者的看法是该参与者的陈述；便利问卷只覆盖实际回答者；转录和同场录音不是独立互证；前后比较没有识别条件时不宣布净因果。目标、未实施方案和条件预测保留各自状态。

真实引语回到实际可核查的原文/录音；只有回顾笔记或摘要时使用限定转述。统计与图表报告实际计算、输入与范围，计划分析留在计划中。

## 3. 缺口如何写进正文

在相关位置用具体标记，如 `[待核查：概念定义与真实文献页码]`、`[待补资料：2024年4月该决策的原会议记录]`、`[范围限制：本次仅有8名便利样本回答]`。这些是演示格式，不要求当前案例出现这些年份或人数。

不要用一段总免责声明掩盖具体缺口，也不为填满章节造事实。能够写出的证据分析照常写；不能确认的机制、效果和贡献分别保留待检验状态。材料核心空缺导致无法分析时，明确交付的是资料整理/研究计划，而不是给空骨架标“论文初稿完成”。

## 4. 交付文件与完成条件

| 文件 | 本轮结束时应能核查的内容 |
| --- | --- |
| 论文草稿.md及08分节草稿 | 连贯正文、章节功能、证据定位、具体缺口；用户要求的篇幅与格式范围明确 |
| 01事实表与02边界/时间线 | 实际材料、主体与单位、形成时间/事件时间、未覆盖范围和争议 |
| 04理论与框架 | 已核查的真实来源、理论任务、工作概念/待核查项及修订依据 |
| 05设计与材料条件 | 真实取样、实际程序及计划/未执行部分，不冒充完成研究 |
| 06证据与解释矩阵 | 当前正文主张、实际来源、推理连接、替代解释和支持范围 |
| 07详细提纲 | 当前正文组织、P/T功能、证据ID及未解决项 |
| 09复核记录 | 实际检查的事实、数字、引语、方法、理论引用与一致性；发现的问题与修订 |
| 执行记录.md | 模板/资料/成果版本、已确定问题、实际分析、当前阶段、下一步与所需文件 |

初稿交付完成的含义：现有资料已经形成实际正文；每个核心主张能回到当前材料；未知事实与未执行程序保持未知；待核查理论与未解决证据有具体位置；复核记录说明实际检查范围。它不等于全部研究已经验证或可以直接投稿。

## 5. 交接

用户已有04—07但缺01/02或原材料定位时，补回原定位后写作；只有提纲不能作为新事实源。用户已有草稿时，从第9步检查并按缺口返回相应步骤，保留已确认决定与旧判断。

下一Agent读取执行记录、01/02、04—07、09与原材料/理论定位，然后继续未完成部分。当前只是结构性核查通过时，保留研究层面的待核查范围，不把脚本退出码当作学术结论。
