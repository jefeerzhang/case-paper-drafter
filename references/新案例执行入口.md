# 新案例执行入口

> V3执行入口。版本基于第三轮训练归纳；正式检验与稳定切换状态见项目报告。入口负责导航和交接，操作规则以同版本《AI执行流程》为准。

## 1. 明确交给Agent的文件

目标是中文工商管理、以《管理世界》类论文为参照。标准执行包只有以下五份核心文件，另加自己的案例材料：

| 核心文件 | 作用 |
| --- | --- |
| 本文件《新案例执行入口》 | 启动、阶段和恢复 |
| [AI执行流程](AI执行流程.md) | 每一步的输入、动作、完成条件 |
| [案例写作手册](案例写作手册.md) | 问题、理论任务、A—H路线和适用条件 |
| [段落与理论卡片库](段落与理论卡片库.md) | 段落功能、表达组织、理论角色及第三轮细化规则 |
| [管理世界写法专题](管理世界写法专题.md) | 目标期刊已有语料的写法观察与边界 |

模板修订记录用于理解版本差异，不是启动必读文件。索引、篇幅参考、文献卡片、原PDF、其他期刊专题是条件资料。只有回读范例、核对短原句或比较篇幅时才加载。缺少条件资料时可以继续分析自己的材料，记录哪些参考来源未回读。

理论卡说明理论如何使用，不能替代真实理论文献。形成定义、引用和理论贡献时必须核查真实来源；尚无来源时保留“待核查”，继续能够执行的材料分析。

## 2. 三种启动方式

**同一电脑、能读取整个项目：**给Agent三个真实路径：稳定入口、新案例材料、独立成果目录。Agent从入口定位V3核心文件。用户可以提供已有问题、草稿和理论文献。

**换电脑：**复制五份核心到同一目录，另提供新案例材料。核心之间用同目录文件名定位；Windows原项目路径不是运行前提。用户不必搬走1131份参考PDF。

**只能读取附件：**上传同版本五份核心及自己的材料。Agent按附件文件名绑定五份文档；不得将Markdown本地链接视为附件读取已经成功。登记真实可读附件、材料定位和成果交付方式。当前平台不能直接保存文件时，按文件名交付各阶段内容。

迁移包可以保留训练来源的doc_id与PDF页码。包中未附原PDF时，这些是来源线索，不能声称本次执行回读原文。

## 3. 按阶段读取与执行

每次启动读取本入口、《AI执行流程》和已有`执行记录.md`。手册、卡片与目标专题按当前任务加载相关部分。附加专题不是条件分支的必读前提；核心手册和卡片已经说明操作。

### 第一次：材料与问题，第0—3步

输出`00-任务范围.md`、`01-材料与事实表.md`、`03-研究问题候选.md`。过程任务输出`02-案例时间线.md`；共时、诊断或规范任务输出`02-案例边界与状态表.md`。

完成条件：事实带材料ID与定位；事件期和资料形成期分开；案例边界及分析单位明确；争议和空缺保留；最多三个问题有材料支持和取舍。问题已经确定时核对材料匹配后继续，不重复选题。未经真实理论核查的缺口不写成创新结论。

### 第二次：理论、分析与提纲，第4—7步

读取00—03、原材料定位和理论来源。输出`04-理论与分析框架.md`、`05-研究设计与材料条件.md`、`06-证据与解释矩阵.md`、`07-论文详细提纲.md`。

完成条件：理论任务与定义可追溯；设计按真实对象和程序选择；实际执行分析后才报告发现；每项解释有来源、构念连接、替代解释和边界；提纲带卡片编号与证据ID。观察方向可以修订，最终框架不得在读取材料前预定。只有计划时交付研究设计，不能冒充分析完成。

### 第三次：分节写作与复核，第8—9步

读取01事实表、02边界/时间线、04—07、`执行记录.md`，保留原材料与真实理论定位。输出`08-分节草稿/`、`09-复核记录.md`及`论文草稿.md`。

完成条件：核心主张能回到当前矩阵、事实和原材料；方法只描述实际程序；理论贡献对话真实文献；图表、正文、单位、状态和数字一致。核心证据缺口未解决时保持研究草稿，并列补充材料需求。

## 4. 直接复制的启动指令

```text
请读取我提供的《新案例执行入口》及同版本五份核心文件。
运行方式：【本机路径 / 同目录迁移包 / 附件】
入口位置或附件名：【真实位置】
新案例材料：【真实路径或附件名】
成果目录或交付方式：【独立目录或按文件名交付】
目标期刊：中文工商管理，以《管理世界》类论文为参照
已有问题、决定、分析或草稿：【填写；没有时写“未确定”】
当前先执行第0—3步，交付材料、边界和最多三个问题候选。
已有问题时检查材料匹配并保留已有决定。
每次保存执行记录；事实来自我的材料。
条件范例缺少时记录未回读范围，继续已有材料分析。
```

## 5. 继续执行与更换Agent

选定问题后：

```text
我选择【问题编号/名称】。读取成果00—03和执行记录，
执行第4—7步，按真实材料建立理论任务、设计、矩阵和提纲。
保留已有决定；理论来源缺少时标待核查。
```

进入写作或交给另一Agent：

```text
读取执行记录，以及01、02、04—07文件。
核对材料和理论原定位，核对矩阵与提纲版本。
执行第8—9步。发现核心缺口时退回对应步骤并保留修订原因。
不得仅根据提纲补造访谈、机制或结果。
```

每次执行写`执行记录.md`，至少包含：模板版本和五核心位置、材料和成果位置、当前阶段、已确定问题/设计/理论任务、事实表及矩阵版本、实际执行的分析、未解决缺口、下一步和所需文件。

恢复时读取现有成果并核对版本。旧假设改成发现时保存新证据和理由；不得默默改变材料身份或把计划改成实际结果。

## 6. 从已有工作开始

| 已有内容 | 起点 |
| --- | --- |
| 零散材料、问题未确定 | 第0—3步 |
| 问题确定、分析未执行 | 核对01/02后第4—7步 |
| 分析与提纲完整 | 核对事实、矩阵和理论来源后第8—9步 |
| 已有草稿 | 第9步，按缺口返回相应步骤 |

研究问题和关键证据发生实质冲突时，展示具体材料与取舍再请用户决策。已有授权下的常规整理、分析、改写和核查继续执行。


> 迁移包说明：本包只包含五份核心。训练来源ID和页码是回读线索；未附的参考PDF不得报告为本次已读。自己的材料和真实理论文献按任务另提供。
