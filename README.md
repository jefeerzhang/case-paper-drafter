# 案例论文初稿 · case-paper-drafter

把自己的案例资料，组织成一篇有来源定位、研究分析和复核记录的中文工商管理案例论文初稿。

这是一个供 Agent 执行的 Skill。它封装当前 V3 写作方法、资料规范、段落与理论卡片，以及三个可选的 Python 辅助脚本。默认参考《管理世界》类学术案例论文的论证方式；用户指定的研究问题、目标期刊和写作阶段优先。

## 从资料到初稿

你提供真实材料，Agent 按材料选择研究路线，形成事实表、证据解释矩阵、提纲和分节正文，最终合并为 `论文草稿.md`。资料不足的位置会保留明确标记，并列出补充任务。

适合三种使用情形：

- 第一次写案例论文：盘点资料，确定问题，推进至初稿。
- 已有研究分析：读取已有成果，从当前阶段继续写。
- 已有初稿：回读证据，核对数字、引语、理论与结论的一致性。

## 安装到 Codex

将整个仓库放入个人技能目录下的 `case-paper-drafter` 文件夹，保持内部结构。

Windows PowerShell：

```powershell
git clone https://github.com/jefeerzhang/case-paper-drafter.git "$env:USERPROFILE\.codex\skills\case-paper-drafter"
```

macOS / Linux：

```bash
git clone https://github.com/jefeerzhang/case-paper-drafter.git "$HOME/.codex/skills/case-paper-drafter"
```

如果目标文件夹已经存在，先检查现有安装。使用自定义 `CODEX_HOME` 时，将仓库放入该目录的 `skills/case-paper-drafter`。安装后新开一个会话，在技能选择器中查找 `case-paper-drafter`，或直接用 `$case-paper-drafter` 调用。

没有 Git 时，也可以下载仓库 ZIP，解压后将文件夹命名为 `case-paper-drafter`，放到同一位置。

## 第一次使用

把资料放在独立的案例目录中。已有目录也可以直接交给 Agent 盘点，不必先全部整理成示例结构。

```text
我的案例/
├── 材料/
│   ├── 问卷/       # 问卷版本、原始答卷、变量说明、清洗记录
│   ├── 访谈/       # 提纲、受访者角色、逐字稿、访谈日期
│   ├── 录音/       # 原始音频、时间信息、对应转写稿
│   ├── 档案/       # 制度、会议记录、经营数据、事件记录
│   └── 参考资料/   # 公开报道、研究文献、来源与获取日期
├── 成果/           # Agent 生成的分析、初稿和复核记录
└── 受限归档/       # 与本次交付范围分开保存
```

保留原件；转写稿、译本和清洗数据另存，并记录与原件的对应关系。资料类型、版本、日期、使用范围和考察要点见[案例资料规范](references/案例资料规范.md)。

在能读取资料的 Agent 会话中输入：

```text
$case-paper-drafter

我的案例资料在：<材料目录的实际路径>
成果请写入：<成果目录的实际路径>
研究问题：<已有问题；没有就写“请根据资料提出候选问题”>
目标：中文工商管理学术案例论文初稿。
请先盘点资料，再按技能流程推进至正文和复核记录。
```

也可以直接提供附件。没有材料时，Skill 会引导提交材料；已有分析或初稿时，一并提供其位置。

## Agent 如何执行

| 阶段 | 实际工作 | 形成的成果 |
| --- | --- | --- |
| 0—3 | 接收材料，区分事实与陈述，确定案例边界、时间范围和问题 | 输入范围、事实表、边界或时间线、研究问题 |
| 4—7 | 选择理论角色和分析路线，组织证据，检验解释，规划段落 | 理论对话、分析方案、证据与解释矩阵、提纲 |
| 8—9 | 写出分节正文，合并草稿，回读来源并复核 | 论文草稿、复核记录、执行记录 |

每次恢复任务，Agent 读取已有成果和执行记录，核对材料版本后继续。过程的完成条件见[新案例执行入口](references/新案例执行入口.md)；具体动作见[AI 执行流程](references/AI执行流程.md)。

最终交付包括论文正文和支撑分析。完成初稿不等于通过学术审稿。理论、数据和引语必须对应实际来源；缺失的证据或文献保持待补标记。详细交付要求见[初稿交付与复核](references/初稿交付与复核.md)。

## 运行条件

- Agent 能读取用户提供的材料，并写入成果目录。
- PDF、表格、Word、音频的实际读取能力取决于当前工具。未能读取或转写的范围会写入记录。
- 辅助脚本需要 Python 3.10+，只使用标准库。没有 Python 时，Agent 可以按文档手工维护同样的登记和执行记录。
- 脚本本身不需要 API 密钥或网络；文献核验、录音转写和模型运行取决于所用 Agent 与工具。

## 可选辅助脚本

| 脚本 | 用途 |
| --- | --- |
| `init_case.py` | 创建成果骨架和阶段登记，保留已有文件 |
| `index_materials.py` | 登记材料编号、哈希、版本和人工元数据 |
| `check_case.py` | 检查结构、证据编号、版本、定位和阶段登记 |

在本仓库根目录运行，替换实际路径：

```bash
python scripts/init_case.py --case-dir "<成果目录>" --core-dir references --name "我的案例"
python scripts/index_materials.py --case-dir "<成果目录>" --materials-dir "<材料目录>"
python scripts/check_case.py --case-dir "<成果目录>" --write-report
```

`--core-dir references` 指向本 Skill 的五份核心文档。初始化只生成骨架；Agent 继续完成研究与写作。结构检查不判断事实真实性、理论贡献、因果机制或投稿质量。完整字段与命令见[脚本使用说明](references/脚本使用说明.md)。
